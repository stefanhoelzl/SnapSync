# architecture-diagrams Specification

## Purpose

Architecture diagrams that cannot lie about the code, because they are derived from it — the
reviewable rendering of the `module-architecture` laws. Hand-drawn diagrams rot (the previous
CLAUDE.md module graph claimed a spine that was never true); prose narratives were retired for the
same reason. Derived diagrams can only be stale, and staleness is mechanically checkable, so the
freshness gate turns rot into a build failure. The flow sequence diagrams and the DI/binary×port
matrices double as instruments: a flow the generator cannot transcribe violates the flow law, and
a wiring difference between binaries — the class of defect behind the per-tier reconciler
regression and the harness-mirror drift — renders as a visible anomalous cell in the PR diff that
introduces it.

Decision record: `changes/archive/2026-07-17-establish-target-architecture` (D9).

## Requirements

### Requirement: Diagrams are derived, never drawn
The repository SHALL contain a generated diagram set under `architecture/`, produced by
`./gradlew architectureDiagrams` from the code and build model alone: the module dependency
graph, the zone/feature graph, one sequence diagram per flow command, the port × adapter matrix
(including a fake-and-contract-test-exists column), feature cards (including the forge
name→sources map), and the DI wiring graphs with the binary × port matrix. Diagrams SHALL be
Mermaid-in-Markdown. Hand-edited content in `architecture/` SHALL NOT survive the freshness gate.

#### Scenario: A wiring difference between binaries becomes visible
- **WHEN** two binaries pass different implementations for the same port without a documented
  reason
- **THEN** the binary × port matrix shows the anomalous cell in the PR diff that introduced it

#### Scenario: A flow the generator cannot transcribe
- **WHEN** a flow command's body falls outside the closed transcriber grammar (straight-line
  feature calls, concurrent fan-out, a `when` over a feature-returned sealed result, a single
  leading guard clause)
- **THEN** generation fails the build, because an untranscribable flow is a law violation, not a
  rendering problem

### Requirement: Generation is byte-deterministic
Diagram generation SHALL be byte-deterministic across machines and platforms: collections sorted
with a fixed code-point comparator, hardcoded `"\n"` line endings, explicit UTF-8, no timestamps,
and no absolute paths in output.

#### Scenario: Two clean runs on different hosts
- **WHEN** `architectureDiagrams` runs twice on the same commit on different operating systems
- **THEN** the generated bytes are identical

### Requirement: Freshness is gated in the canonical build
An ordinary test in the architecture-guards module SHALL regenerate the diagrams (consuming the
module-graph task's declared output rather than parsing build scripts) and compare against the
committed files, failing with the diff and the regeneration command when they differ. The test's
declared inputs SHALL include the committed diagram files, `settings.gradle.kts`, and every
`build.gradle.kts`, so staleness cannot hide behind build caching. The gate SHALL NOT rely on
`git diff` (fails open on untracked files, lives outside `./gradlew build`, assumes a clean
tree).
In CI, the required `diagrams` check of the `architecture` workflow SHALL regenerate on a clean
checkout and fail on any resulting difference, including untracked files — which also covers the
module-graph sidecar's self-staleness. There SHALL be no self-healing on the default branch: a
semantically stale merge surfaces as this required check red on the merge commit, fixed by a
regeneration PR.

#### Scenario: A structural change without regeneration
- **WHEN** a PR changes the module graph, a flow body, or a port implementation without running
  `architectureDiagrams`
- **THEN** `./gradlew build` fails locally and in CI with the diff and the command to run
